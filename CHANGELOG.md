# История изменений

## 1.5.4 — 2026-11-16

### Исправлено
- Вместо «Не удалось проверить обновления (нет сети?)» показывается настоящая
  причина: сертификат, лимит запросов GitHub (бывает в офисной сети с общим
  адресом), тайм-аут, нет DNS, прокси.

### Важно для 1.5.2
- Версия 1.5.2 на компьютерах без корня ISRG Root X1 в хранилище Windows не может
  обновиться сама: сервер, с которого GitHub отдаёт файлы релизов, использует
  сертификат Let's Encrypt с тем же корнем. Скачайте exe со страницы Releases
  вручную один раз — начиная с 1.5.3 обновление проходит.

## 1.5.3 — 2026-11-16

### Исправлено
- **Сертификат всё ещё отвергался на части компьютеров** («цепочка прервана на
  корневом сертификате, у которого отсутствует отношение доверия»). Так бывает, когда
  групповая политика отключает автообновление корневых сертификатов Windows: нужный
  корень (ISRG Root X1) в хранилище так и не появляется. Chrome и Edge этого не
  замечают — у них собственный список доверенных центров. Теперь в этом случае
  проверка повторяется по хранилищу Windows вместе со списком доверенных центров
  Mozilla (пакет `certifi`). Самоподписанный сертификат и чужое имя по-прежнему
  не принимаются.
- **Окно настроек растягивалось на весь экран** при длинном сообщении об ошибке:
  у строки состояния не было переноса. Теперь текст переносится, а лишняя ширина
  достаётся полям ввода.

### Тесты
- `tests/tls_fallback_test.py` — локальный HTTPS mock-NAS с сертификатом
  одноразового тестового центра: корня нет в Windows → запасная проверка
  подключается; сертификат неизвестного центра отвергается.

## 1.5.2 — 2026-11-16

### Исправлено
- **Ошибка сертификата при подключении по имени** (например, `dsm.example.ru`
  с wildcard-сертификатом Let's Encrypt), хотя браузер сертификат принимает.
  Python сверял цепочку только с корневыми сертификатами, уже лежащими в хранилище
  Windows, а Windows докачивает их по требованию — на части компьютеров нужного
  корня (ISRG Root X1) там ещё нет. Теперь сертификат проверяет сама Windows
  (пакет `truststore`), результат совпадает с браузером. Это же касается
  проверки обновлений на GitHub.
- Понятные подсказки к ошибкам сертификата: подключение по IP к сертификату
  на имя, чужое имя, истёкший срок, самоподписанный сертификат. Раньше на любую
  ошибку советовалось снять галочку проверки.
- **Мелкий интерфейс на 4K и при масштабе 150–200 %.** Программа объявляла
  поддержку DPI уже после создания окна: Tk считал экран обычным (96 DPI), а
  Windows переставала растягивать окно. Теперь режим DPI включается до создания
  окна, шрифты, отступы, размеры окон, колонки и высота строк масштабируются.

## 1.5.1 — 2026-11-16

### Исправлено
- **magnet-задача застревала в «Проверке» после выбора файлов.** Пока открыто окно
  выбора, программа снимала wanted со всех файлов, а Download Station переводит
  задачу без единого нужного файла в «Проверку» (статус 6) и сама из неё не выходит.
  Теперь на время выбора остаётся включённым один самый маленький файл (обычно
  субтитры или .nfo на несколько КБ). После выбора сначала включаются выбранные
  файлы, потом выключается временный. Раздачу из одного файла программа не трогает.
- Страховка: если задача после выбора всё-таки стоит в «Проверке», ничего не
  скачав, программа один раз ставит её на паузу и возобновляет.
- Если Download Station не принял выбор файлов, появляется предупреждение.

### Тесты
- `tests/magnet_select_test.py` — у задачи ни на миг не остаётся ноль нужных файлов.
- `tests/e2e_magnet_live.py` — magnet через настоящее окно на живом NAS
  (открытая раздача Sintel; задача и её папка удаляются в конце).

## 1.5.0 — 2026-11-15

Исправления по итогам ревью.

### Исправлено
- **Обновление при запущенном мониторе.** Монитор работает из того же exe, и раньше
  замена файла падала, оставляя программу не обновлённой и не запущенной. Теперь
  обновление останавливает монитор, отодвигает старый exe в `*.old` (переименовать
  запущенный файл Windows разрешает), ставит новый и перезапускает программу и монитор.
- **Удаление не удаляло exe.** `timeout` без консоли завершался сразу, а `del`
  запускался, пока процесс ещё жив. Теперь файл удаляет скрытый PowerShell после
  выхода процессов программы; монитор перед удалением останавливается.
- **Уведомления о завершении.** Учитывается статус 8 («завершена, раздаётся»):
  раньше задачи, ушедшие на раздачу, уведомления не давали. Монитор видит все задачи
  (постранично), а не первые 100, и запускается в единственном экземпляре.
- **Поиск задачи мог задеть чужую.** Совпадение «по подстроке имени» убрано.
  Дубликаты определяются по info-hash (magnet) или точному имени и только для
  предупреждения. Если NAS не вернул id новой задачи, она ищется только среди задач,
  появившихся после отправки, — старая задача с похожим именем больше не может
  быть изменена или удалена по «Отмене».
- Тайм-аут при чтении ответа NAS теперь даёт понятную ошибку на русском и
  включает запасные пути, а не обрывает поток.
- Нельзя отправить задачу без единого выбранного файла.
- Несуществующая папка назначения проверяется заранее; приложение предлагает её создать.
- Отмена и закрытие окна больше не «замораживают» его при недоступном NAS.
- Выключение перехвата возвращает прежний торрент-клиент и не удаляет чужие записи
  `.torrent\OpenWithProgids`.

### Безопасность
- Обновление проверяется по SHA-256, который GitHub публикует для файла релиза, и по размеру.
- Вход в DSM — POST-запросом: пароль не попадает в строку запроса.
- По умолчанию для новых настроек — HTTPS, порт 5001; порт следует за галочкой HTTPS.

### Прочее
- Журнал ротируется при 1 МБ (3 копии), длинные списки в нём сокращаются.
- Пути перехвата, автозагрузки и записи «Приложения» сами переводятся на exe,
  если его переместили или скачали заново.
- Хвосты обновления (`*.old`, временный exe) удаляются при запуске.
- Версия видна в свойствах exe.
- Новые тесты: монитор, межпроцессная остановка, замена занятого exe, реестр,
  удаление, журнал, сценарий окна добавления, проверка на живом NAS.
- Документация обновлена (устаревшие разделы README исправлены).
